# EL0-to-workspace IPC: integration diagnosis

**Status: design only. No new guest, connection or VM test is claimed.** The existing components can support a narrowly scripted experiment in principle, but their current composition does not establish a safe connection from two EL0 tasks to the graphical guest's document. In particular, there is no verified task-to-workspace identity binding and the current MCP edit path accepts caller-supplied actor names. Reusing those names as credentials would make the advertised non-impersonation property false.

## What actually exists

- [`concurrent_isolation`](../concurrent_isolation/) has two fixed EL0 loops with distinct TTBR roots, private physical pages and an interleaved EL1 graphical service. Its lower-EL AArch64 synchronous-exception vector branches to `irq_fatal`; an `SVC` from either loop therefore cannot currently reach a document. Its address-translation checks are probes, not actual forbidden access faults. The loops have no document protocol.
- [`user_ipc`](../user_ipc/) is a **different guest** with an EL0 SVC handler and fixed per-actor phases, expected instruction addresses and synthetic buffers. It checks `CURRENT`, TTBR and bounded pointers in its deliberately restricted scenario; its eight-call state machine is not a general IPC service or an authentication facility. Interrupts are masked in that fixture; its handler and scheduler have not been integrated with the graphical guest's timer/IRQ paths.
- [`decision_vm`](../decision_vm/) stores its `DocumentDemo` and router as local state in a running EL1 service loop. Its MCP `document_edit` accepts `actor` and `space` labels over an unauthenticated channel; the [`workspace_bridge`](../workspace_bridge/) verifies registry relationships between labels but does not authenticate the sender. These labels are not identities of a physical person or an AI. The separate [`journal_vm`](../journal_vm/) logs only selected inference-handler results and does not fix this authority gap.

## Proposed narrow contract, not implemented

1. Define two immutable kernel task records for the test, each binding a task ID and its expected TTBR/root to exactly one synthetic workspace role. Upon lower-EL SVC entry, save a complete integer frame, verify exception class and origin, check the scheduler's current task and active TTBR against the kernel-owned record, and reject mismatches. The role and destination are derived from this record, never from user-supplied actor or space labels. Bindings represent only these synthetic tasks; they do not authenticate people, software, or hardware.
2. Define a versioned, bounded request with an operation, request ID, lengths, key and optional value. Do not accept a destination identity in this first ABI; an attempted extra destination field must be rejected. Require checked integer arithmetic and bounds, valid encoding and per-field limits before queueing. Use a dedicated private request page for each task rather than treating the existing marker/stack page as an unrestricted message buffer. Under the fixed immutable mappings, verify the complete range, copy into a bounded kernel-owned buffer while the appropriate address space is active, and use only that copy thereafter. A direct EL1 load can still fault; this is not general fault-tolerant user-memory copying. Never hold an EL0 pointer across a root change or defer dereferencing it.
3. Use a bounded kernel-owned request queue and paired completion slots with explicit full/error responses. The SVC handler only validates and copies; it must not call the document bridge, allocate, wait for a service, print to UART or touch VirtIO. On queue exhaustion reject the submission without mutating either document or reporting an edit as complete. Define request IDs, ownership, delivery, duplicate handling and task teardown before claiming reliability.
4. At a controlled EL1 service-loop boundary, with no competing document borrow, the single document owner drains a bounded number of requests, maps the trusted task record to the matching bridge role, performs an edit and publishes its response. A task polls its own completion without blocking the only CPU. An accepted submission is not a completed edit until the service has applied it and returned the paired result. Handle IRQ masking, ELR/SPSR, stack lifetime, TTBR switching, GIC/timer EOI and restoration exactly; do not rely on the bump allocator being reentrant or imply arbitrary EL1 preemption.
5. Prevent bypass: for a non-impersonation demonstration the MCP interface should be read-only for documents, or a distinct demonstrably authorized control path must be designed. The existing unauthenticated `document_edit` cannot coexist with a claim that only task A can change A's document. Reading results through MCP proves observation, not caller authentication. Document provenance reports merge origin, not cryptographic identity or an authenticated audit trail.

## Required QEMU evidence before calling this integrated

- Task A and task B independently submit edits; only their kernel-bound copies change, and MCP reads both resulting snapshots and origin/conflict information. Prove requests originated in the corresponding EL0 contexts, rather than constructing them in the host or service.
- Attempt to claim the other role, change the other copy, and use unknown opcodes, malformed encodings, overlong messages, an address crossing the page, unmapped addresses and integer-overflow ranges. Verify correct error, neither copy changes and no mailbox/queue corruption. Include actual controlled faults only if a fault-recovery mechanism is implemented; translation probes alone cannot demonstrate that.
- Fill the queue, verify a real full response without fake completion or discarded prior work, drain it, observe ordered completion and exercise duplicate IDs. Record the submitted/rejected counts with bounded synthetic metadata, not private contents.
- Capture active task and TTBR/ASID at SVC entry and every return; verify full frame restoration, kernel stack bounds, service continuation, timer/IRQ masking and GIC EOI. Show both tasks and service progress while MCP interaction runs; distinguish interleaving on one CPU from parallel execution and do not imply an elapsed-time latency guarantee.
- Verify document/snapshot integrity, restart behavior when applicable, no accesses outside synthetic temporary VM devices, and unchanged pointer and graphical state where the scenario requires it. Test modern and legacy virtual VirtIO paths separately. Failure injection must not be described as a real power-loss durability test.

## Why implementation is deferred

A safe implementation requires a combined SVC/IRQ entry and return path, a trusted task-to-role table, non-reentrant queue ownership and response semantics, plus removal or authorization of the competing MCP edit route. None is present as an integrated mechanism. The standalone SVC's fixed call-site checks do not establish those properties in the graphical service, and a host-generated document edit would not demonstrate EL0 IPC. This diagnostic intentionally does not substitute a simulated connection or report unperformed tests. Independent review of the future code and VM evidence is required before publication as an integrated result.
