# FIFO workspace IPC: integration diagnostic

**No FIFO guest is implemented or tested in this directory.** The previous [`workspace_ipc_vm`](../workspace_ipc_vm/) guest has two idempotent one-shot actor bitsets, fixed opcodes and one copied scalar per actor. It does not provide a FIFO, message IDs, a reusable queue or completion consumption. Its service derives document keys and values from the scalar. Those slots must not be renamed or reported as a queue.

## Concrete integration blockers

1. A real queue requires preallocated kernel entries holding the copied message and its kernel-derived task identity, not just a bitset. Guest key/value bytes need their own bounded format and copying; the existing fixture copies only an eight-byte scalar from a fixed offset. Generic EL0 pointers need overflow-safe full-range checks against the active immutable page and fault handling; the existing direct EL1 loads are safe only under the fixture's fixed QEMU mappings and provide no recoverable copy primitive.
2. Existing timer IRQ checks expect fixed register sentinels and exact saved flags in both assembly loops. Tasks that build messages, issue several SVCs and read replies will use additional registers and may change condition flags. The IRQ validator, exception frame restoration, PC bounds and test sentinels must be adapted together; removing checks or relying on a few successful timings would not prove safe preemption. The EL1 service must retain exclusive document/allocator/driver ownership and drain only after a slice, never from an IRQ or SVC handler.
3. Completion capacity must be reserved along with a queued request. A response must be correlated to the trusted task and request ID and delivered before a slot is reused; `accepted`, `applied` and `consumed` are different states. Reject duplicate IDs and full queues without changing the document or overwriting an earlier response. A polling task must return to the scheduler so the sole EL1 service can drain; an EL0 busy wait that prevents service progress deadlocks the experiment.
4. The MCP document mutation routes must remain absent, since that socket is unauthenticated and labels are forgeable. The fixed `CURRENT`/TTBR binding identifies a QEMU task, not a person or AI, and does not authenticate another external client. MCP reads alone do not establish security or real-world identity.

## Suggested bounded contract

Use an immutable task-to-role table indexed only after checking SVC origin, `CURRENT`, and the active TTBR. Reserve separate fixed request/reply regions inside each task's own QEMU page, with page/offset bounds and checked arithmetic. One candidate fixed message is `{version, request_id, opcode, key_len, value_len, key_bytes, value_bytes}` with small explicit maximum lengths and no caller-controlled role. Copy it to a preallocated kernel entry before validating encoding, operation, lengths, target and sequence; never retain user memory across a root switch. All input is synthetic. These are proposed fields, not an implemented ABI.

With a one-CPU IRQ-masked kernel critical section, append valid requests to a fixed FIFO with explicit head and length. Keep the document and normal allocations exclusively in the service, which drains a bounded number of requests between slices, derives the role from the kernel entry, applies each valid mutation in FIFO order, and publishes a completion for the same task and ID. A full FIFO or invalid input must produce a rejection without modifying queued requests or documents. The queue, completions, and service loop need invariants and independent review before any security claim. The direct-copy and IRQ conditions do not generalize to SMP, mutable page tables, real devices or actual fault recovery.

## Evidence required

- Each actual EL0 task writes multiple distinct synthetic key/value messages into its private page, submits them and **reads and verifies** its own completion. Service responses and MCP snapshots establish FIFO application order and provenance without a host-generated edit.
- Exercise a real full queue, no mutation on rejection, drain and retry, ring wraparound, duplicate IDs, response capacity exhaustion and no overwrite of an earlier completion. Merely checking a `Full` branch or a bitset is insufficient. With exactly two actors, queue capacity two and **only one request in flight per actor**, a third valid request cannot reach the full queue. The test must permit a second outstanding request, add a third task or use a smaller queue with a controlled scheduler; the chosen completion protocol must support that scenario.
- Validate wrong-role claims and malformed/overlong/invalid-encoding messages, crossings of page boundaries and arithmetic overflow with no document or queue mutation. If fixed offsets make a negative pointer unreachable, report that test as unperformed rather than fabricating it.
- Preserve and inspect IRQ/SVC frames, masks, TTBR/ASID, PC and user stack for both tasks across submission, service and completion. Check progress during MCP/QMP operation, compare copies and provenance, and verify a separately created temporary QEMU disk stays untouched. Repeat modern and legacy VirtIO-MMIO and keep synthetic I/O logs.

No tests were run for this diagnostic. Existing evidence for the earlier fixed-slot guest does not prove the proposed FIFO, task-consumed completions, saturation, message integrity or production isolation. A future implementation requires an independent review and actual QEMU evidence before claiming any of those properties.
