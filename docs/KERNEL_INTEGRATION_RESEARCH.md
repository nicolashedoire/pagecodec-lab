# Integrating the QEMU experiments into a kernel

This document describes an integration plan and bounded integration steps, not a complete kernel. The [EL0 guest](../experiments/user_mode/README.md), [preemptive blocking guest](../experiments/preemptive_blocking/README.md), [graphical interaction guest](../experiments/graph_interaction/README.md), [frame allocator model](../experiments/memory_core/README.md) and [storage recovery guest](../experiments/graph_crash_recovery/README.md) each provide evidence for their own scenarios. Their separate successes do not establish that all these mechanisms work together.

The new [`kernel_integrated` guest](../experiments/kernel_integrated/) combines MMU setup, a controlled EL0 permission fault and SVC return, and a virtual-timer IRQ through one EL1 vector table. The timer is armed **after** the final EL0 SVC and interrupts an EL1 wait loop: this is not EL0 preemption or scheduler integration. The separate [`graph_unified` guest](../experiments/graph_unified/README.md) combines synthetic graphical interactions and two-slot document snapshots under QEMU, using its own runtime and MMU-disabled HAL. These are separate binaries; neither is a complete operating system.

Two further QEMU guests make narrower integration steps. [`graph_mmu`](../experiments/graph_mmu/README.md) runs the graphical, MCP and synthetic block workflow with an EL1 identity map enabled and caches disabled, with [modern](../experiments/graph_mmu/evidence/graph-mmu-evidence.json) and [legacy](../experiments/graph_mmu/evidence/graph-mmu-legacy-evidence.json) VirtIO traces. Separately, [`el0_preemption`](../experiments/el0_preemption/README.md) demonstrates timer-driven selection of two actual EL0 loops in one shared address space; its [recorded trace](../experiments/el0_preemption/evidence/el0-preemption-evidence.json) does not cover a syscall or real EL0 fault. Neither guest integrates the other guest's functionality or a general process scheduler.

[`system_vm`](../experiments/system_vm/README.md) combines those two fixtures in **one QEMU image**, sharing a page table and exception vector. Each boot first preempts two fixed EL0 loops for eight timer IRQs, then stops the timer, masks interrupts and starts the graphical/MCP/snapshot phase. The phases are sequential: the EL0 loops are not graphical applications and do not run alongside the interface. Both loops share one address space, and permission checks use translation probes rather than a real EL0 fault or SVC. Its [modern](../experiments/system_vm/evidence/system-vm-evidence.json) and [legacy](../experiments/system_vm/evidence/system-vm-legacy-evidence.json) traces document the synthetic workflow, not a complete or isolated operating system.

[`concurrent_vm`](../experiments/concurrent_vm/README.md) extends this with a voluntary EL1 service yield after completed requests/input or after 20,000 polls, then two EL0 timer IRQs before service resumes. Its [modern](../experiments/concurrent_vm/evidence/concurrent-vm-evidence.json) and [legacy](../experiments/concurrent_vm/evidence/concurrent-vm-legacy-evidence.json) QEMU traces show both EL0 counters progress around synthetic MCP, click and snapshot operations. It is single-CPU interleaving between service turns, not arbitrary EL1 preemption, multicore parallelism or an assurance of latency. The EL0 loops share pages; actor labels and MCP are unauthenticated, with no general process or DMA isolation.

The separate [`address_spaces`](../experiments/address_spaces/README.md) guest constructs two TTBR0 roots with ASIDs 1 and 2. Two EL0 loops access the same virtual address through distinct physical pages, write and check separate sentinels, and alternate via timer IRQs; the [QEMU trace](../experiments/address_spaces/evidence/address-spaces-evidence.json) records that fixed scenario. Selected forbidden kernel and physical-identity accesses are checked by AT translation queries, not real EL0 faults. Each switch performs a full local TLB invalidation, so the test does not prove retained translations, ASID reuse or scalable shootdown. It does not establish general process or DMA isolation and is not integrated with `system_vm`.

The separate [`process_isolation`](../experiments/process_isolation/README.md) guest extends that scenario with two **real EL0 read faults**: each task attempts to read the other page through its privileged physical-identity mapping. The handler checks the fault syndrome, address, instruction, active root and actor before skipping that exact load, and the tasks continue to exercise their own private aliases. Its [QEMU evidence](../experiments/process_isolation/evidence/process-isolation-evidence.json) covers these particular reads and subsequent checks. No forbidden write is attempted, and neither general process isolation nor DMA isolation follows from this fixture. It is not integrated with `system_vm`.

## Where the prototypes meet

| Concern | Current evidence | Work needed for a common guest |
| --- | --- | --- |
| Entry and runtime | Each standalone guest has its own boot code, linker script, console and failure handling. | Define one entry point, linker layout, initialization sequence and serial/error interface. Keep the standalone experiments for regression. |
| Memory | [`user_mode`](../experiments/user_mode/src/main.rs) installs a fixed identity-mapped page table for its image and UART. [`memory_core`](../experiments/memory_core/README.md) tracks a caller-provided synthetic pool; it does not discover or map RAM. | Establish a trusted QEMU RAM and reservation map, account for the kernel, stacks, tables and device buffers, then connect frame ownership and page mappings. A returned frame address is not automatically safe to dereference. |
| Interrupts and exceptions | [`kernel_integrated`](../experiments/kernel_integrated/src/main.rs) uses one table for lower-EL synchronous exceptions and a subsequent EL1 GICv2 timer IRQ; [`preemptive_blocking`](../experiments/preemptive_blocking/src/main.rs) remains a separate guest. | Extend context and dispatch for EL0 preemption and scheduler integration; verify state beyond the selected fixture. |
| Scheduling | [`el0_preemption`](../experiments/el0_preemption/README.md) switches two fixed EL0 loops with a two-ID ring in one address space. The separate [`address_spaces`](../experiments/address_spaces/README.md) fixture adds two roots and ASIDs for one private page each. | Integrate syscall/exception handling and the address-space fixture with task lifecycle, synchronization and genuine block/wake events; both fixtures have fatal EL0 SVC/fault vectors. |
| Heap and DMA | [`graph_interaction`](../experiments/graph_interaction/src/main.rs) uses a finite non-reclaiming bump heap and a static DMA arena. | Provide a bounded, correctly synchronized heap and explicit buffer ownership, failure behavior and eventual reclamation. No heap allocation or logging in IRQ context. |
| VirtIO and graphics | [`system_vm`](../experiments/system_vm/README.md) runs virtual GPU, tablet and block through the [patched VirtIO dependency](../experiments/virtio_fix/) after its EL0 probe, under a cache-off identity map. | Run real tasks and graphical services concurrently, and establish ownership, lifetime and DMA isolation requirements. |
| Documents and persistence | [`graph_unified`](../experiments/graph_unified/README.md) combines interaction and two-slot snapshots using a temporary virtual block device, but retains its own runtime. | Integrate those services into the shared kernel and test interrupted writes; the current stage/SIGTERM fixture does not prove atomicity. |

### MMU and DMA mismatch

The original graphical guest's `VmHal` assumes a single CPU with **MMU and caches disabled**, and identical guest virtual and physical addresses. `kernel_integrated` maps GIC but not VirtIO MMIO or DMA. `graph_mmu` adapts the graphics fixture to a cache-off identity map and checks every page of a shared range before returning a device address; it accepts writable image ranges including stack and page tables. This is not IOMMU isolation, authorization, or a general ownership/lifetime guarantee. Further integration must establish mapping, pinned-buffer lifetime, coherency, access direction and completion contracts. Successful QEMU tests do not prove native Apple DMA behavior.

### Rust and exception safety

The shared implementation must make each `unsafe` boundary explicit: valid physical and virtual ranges, checked arithmetic, alignment, unique mutable ownership, volatile MMIO, DMA lifetime, stack bounds and synchronization. Static mutable state and raw-pointer access in isolated single-CPU demos cannot simply be reused as a concurrency model. Preemption must not observe partially initialized data; IRQ paths must not allocate or block. Page-table changes require architecture-correct translation maintenance and barriers. Context switching must preserve all state the supported tasks actually use; the present demos do not save general FP/SIMD context. Unrecognized exceptions need a defined failure path rather than silently continuing.

## Ordered milestones

1. **Common boot:** one QEMU `virt` guest, one linker and entry point, UART and a recorded smoke test. Define its CPU count and virtual platform configuration.
2. **Memory foundations:** establish RAM bounds and reserved ranges, integrate frame metadata without overlapping ownership, map image, stacks, UART, GIC, VirtIO MMIO and device buffers with appropriate attributes, and test valid and invalid mappings. Define zeroing and allocation-failure behavior.
3. **Unified exceptions:** `kernel_integrated` demonstrates one vector table, a controlled EL0 synchronous exception and a subsequent EL1 virtual-timer IRQ with acknowledgement and return. Extend this to interrupts during user execution and other exception paths; keep interrupts masked until setup is complete.
4. **Task and allocation contracts:** implement bounded task states and heap ownership; test queue integrity, exhaustion, blocking and waking without allocation or serial output inside IRQ handlers. Add stack bounds and explicit context preservation tests.
5. **EL0 plus scheduling:** `el0_preemption` preempts two loops in one address space; `kernel_integrated` separately exercises syscall and denied-access paths. Combine those paths using common context and address-space contracts and test failure cases.
6. **Devices and services:** `concurrent_vm` tests graphical input, MCP and temporary virtual storage interleaved with fixed EL0 loops at voluntary service boundaries. Extend the task/IRQ design, ownership and failure cases before claiming general concurrent services or arbitrary EL1 preemption.

Each stage should record the exact guest image, virtual platform, inputs, outputs and limitations. Benchmarks are meaningful only after functional integration. Nothing in this plan proves a boot path, driver compatibility or installation readiness on a physical Mac; those require separate platform-specific engineering and verification.
