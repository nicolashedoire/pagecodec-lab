# Full household corpus results

Generated by `python3 scripts/summarize.py` from the committed measurement JSON.

One UCI source corpus, four representations/partitions. All 20 method cases passed exact byte round-trip verification. Each input uses 16 KiB pages, one warmup per method and nine timed trials with shuffled method order. Times are median milliseconds for the complete input. Brackets show the observed minimum and maximum, not confidence intervals.

Host: Apple M4 Pro, 24 GiB RAM, macOS 15.1.1, Apple clang 16, `-O3`. This single desktop run is not evidence of lower operating-system RSS or faster applications. The source and compressed representation coexist during the benchmark. Existing swap use was present; global VM snapshots are context, not a measurement of this process's memory savings.

## Interpretation

The fixed criterion is: stored bytes no larger than the reference, median encoding time at most 90% of the reference, and median decoding time at most 90% of the reference. Paired-round counts are descriptive checks on the nine collected rounds; they are not a significance test.

**0/4 inputs satisfy this criterion against all three Apple references.** The column-major numeric input satisfies it against both LZ4 variants, while LZFSE retains a size advantage. The row-major layout trades greater size for lower codec time. The original text largely falls back to raw bytes, so its fast custom timing is not a compression victory.

The same frozen V2 codec was used for every input. No codec adjustment followed these new measurements. The four inputs remain representations/partitions of one dataset, and the earlier synthetic wins are not independent validation of this real corpus.
