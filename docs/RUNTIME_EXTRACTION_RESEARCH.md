# QEMU runtime extraction research

This is a read-only analysis of three experimental guests: [`workspace_queue_dynamic`](../experiments/workspace_queue_dynamic/), [`workspace_dynamic_storage`](../experiments/workspace_dynamic_storage/) and [`decision_vm`](../experiments/decision_vm/). These are single-CPU QEMU fixtures, not a common production kernel. The two priorities below target measured duplication without changing guest semantics or suggesting that either extraction provides native Apple support.

## 1. Share the identical QEMU page-table module

The three files `src/mmu.rs` in the guests listed above are byte-for-byte identical at this analysis point. Their SHA-256 is `dc41541d9cbac5d6d902717778486d399f8f4fb8ed6eeb26aeaeef6b81cea331`. Each builds two immutable TTBR0 roots, identity-mapped privileged QEMU RAM/devices and separate user aliases, exports `ROOTS`, and provides the same `init`, `root`, `active_root`, `switch_root`, `identity_range` and `shareable_range` functions. The common 97-line source is a stronger extraction candidate than the evolving SVC programs.

Proposed ownership: a new `experiments/qemu_mmu_core/` Rust `no_std` crate owns the current module, constants and tables; an integration owner touches one guest at a time to consume it through a path dependency. Keep the current initialization inputs and the `ROOTS` link symbol/ABI initially. Let each guest retain its own startup, linker script, private pages, exception vectors, `el0.rs` and VirtIO HAL. Do not turn QEMU addresses into a promised hardware abstraction or silently broaden the HAL's allowed ranges.

The exact linker symbols, alignment, static table layout, local TLB invalidation, MMIO flags and single-CPU cache-off assumptions are invariants. `ROOTS` is referenced from assembly; link-time optimization, object retention, renamed exports or moved static storage could change placement or break those references even when Rust compiles. The heap, DMA, linker regions and page-table bounds must remain separate. `shareable_range` currently describes this guest's QEMU identity mapping; it is not proof of DMA ownership or IOMMU isolation.

For each migrated guest, keep the pre-extraction evidence as historical evidence. Build a new binary and run its existing QEMU harness with modern and legacy transports. Check the image hash and QEMU version, boot and translation probes, root/ASID transitions, timer progress, EL0 frame and service-boundary checks, synthetic MCP/QMP interactions, and any storage/no-mutation checks that belong to that guest. Record new evidence tied to the new binary. Output parity is observable scenario parity, not proof of all translations, timings or hardware.

## 2. Share the bounded snapshot codec, not device operations

[`workspace_dynamic_storage/src/main.rs`](../experiments/workspace_dynamic_storage/src/main.rs) and [`decision_vm/src/main.rs`](../experiments/decision_vm/src/main.rs) contain the same `parse_document`, `checksum_slot`, `encode_snapshot`, `decode_slot` and `select_slots` logic. The former also owns `read_pair` and `save_snapshot`; device access and the ordering of writes and flushes should initially remain guest-specific. The queue-only guest does not persist snapshots and should not gain a storage dependency just for symmetry.

Proposed ownership: a new `experiments/snapshot_codec/` `no_std + alloc` crate owns only the `GSLOT001` record format, bounded document parsing, commit-marker/checksum verification and two-slot selection; an integrator adapts the existing document-bridge conversion separately for each storage-using guest. Preserve the exact 4096-byte wire layout, offsets, FNV-1a calculation, canonical zero padding, commit marker, generation ordering and distinction between a blank pair and a corrupt/uncommitted pair. Avoid a generic persistence framework. JSON decoding and document reconstruction still require `alloc`; the codec alone does not guarantee bounded allocation for every malformed input or an authenticated snapshot.

Before replacing each caller, compare encoded bytes and decoded selections for the same synthetic documents. Run the existing independent slot decoder and QEMU scenarios for blank storage, commit and second-VM restore before edits, the decision guest's staged/corrupted cases, and both MMIO transports where their respective harnesses support them. Add a duplicate-generation case before claiming that branch is covered. Include failure/no-mutation checks and new hashes in new evidence. A returned flush is not proof of a negotiated FLUSH command, crash durability or atomicity; FNV is not authentication. Extraction must preserve rather than upgrade these claims.

## Later candidates and boundaries

The three graphical `main.rs` files also repeat a QEMU-only bump allocator, VirtIO HAL, UART and drawing helpers. They depend on singleton statics, linker layout, DMA address checks and guest-specific service behavior; extract them only after the two narrower changes have passed in their callers. The two FIFO guests share much of `el0.rs`, but the storage guest already differs in request kind, completion count, save authorization and task acknowledgment. `decision_vm` has a different EL0 workload. A later **pure, preallocated FIFO state machine** could share queue/duplicate/completion invariants, but the opcode mapping, active TTBR check, user copying, task scripts, IRQ validation and save policy should remain local until a common contract is demonstrated. This avoids conflating synthetic actor labels with authenticated identities or claiming a generic scheduler.

No source files, images or historical evidence were changed for this analysis. The extracted crates, integration steps and parity tests are recommendations; they have not yet been implemented.
